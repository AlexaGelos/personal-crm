# Группы контактов - как сделать

## Context

- Зачем и что меняется - в `proposal.md`, поведение - в `specs/contact-groups/spec.md` и `specs/keep-in-touch/spec.md`
- Сейчас в базе две таблицы: `contacts` и `notes` (`src/db/schema.ts`), миграции `drizzle/0000_init.sql` и `drizzle/0001_keep_in_touch.sql`
- Чтение данных - в `src/lib/data.ts` (`server-only`): `listContacts(query, limit)`, `countContacts(query)`, `getContact(id)`, `listOverdueContacts(limit?)`. Запись - прямо в server actions в `src/app/actions.ts`, вместе с `revalidatePath` и `redirect`
- Состояние главной хранится в адресе: `q` - поиск, `limit` - сколько показано, `due=all` - блок «Пора связаться» раскрыт. `SearchBox` при вводе оставляет в адресе только `q`
- Формы - `useActionState`. После ошибки React сбрасывает форму, введённые значения возвращаются через `state.values` и `defaultValue`
- Переключатель частоты (`FrequencySwitch`) - обычная форма с кнопками отправки: работает и до загрузки JavaScript. Выбранная кнопка - `variant="default"` и `aria-pressed`, остальные - `outline`
- Удаление контакта - `DeleteContactButton` с `AlertDialog` из shadcn/ui
- Автотестов в проекте пока нет. `CLAUDE.md` требует TDD, а Vitest и Playwright уже записаны в стек. В этой фиче появляется только Vitest; Playwright и CI будут отдельным изменением
- Тестовые контакты Данте (`pnpm db:seed:dante`) уже загружены локально и на сервере. Скрипт ничего не добавляет, если Вергилий уже есть в базе

## Goals / Non-Goals

**Goals:**

- Миграция только добавляет таблицы: старый образ работает с новой базой, откат образа не требует отката миграции
- Правила групп проверяются тестами на настоящей базе: уникальность названия без учёта регистра и разницы «ё» и «е», удаление группы не трогает контакты, фильтр по группе в списке, поиске и блоке «Пора связаться»
- Выбранная группа хранится в адресе, как поиск и раскрытый блок: «Назад», обновление страницы и другой браузер показывают то же самое

**Non-Goals:**

- Тесты server actions и экранов: `revalidatePath` и `redirect` работают только внутри Next.js. Экраны проверят e2e-тесты позже, сейчас - проверка руками
- Playwright, CI
- Кэширование списка групп

## Decisions

### Хранение

Две новые таблицы:

- `groups`: `id` (identity), `name` (`text not null`), `created_at` (`timestamptz`, по умолчанию `now()`). Уникальный индекс `groups_name_unique` по ключу названия `lower(translate(name, 'ёЁ', 'еЕ'))`: в одном индексе и защита от дублей без учёта регистра и разницы «ё» и «е», и быстрый поиск группы по названию. Та же замена «ё» на «е» уже есть в поиске по имени контакта (`src/lib/data.ts`)
- `contact_groups`: `contact_id` → `contacts.id` и `group_id` → `groups.id`, оба `on delete cascade`, первичный ключ `(contact_id, group_id)`. Отдельный индекс `contact_groups_group_id_idx` по `group_id` - для фильтра, числа контактов в группе и удаления группы

Почему так:

- Отдельная таблица связей, а не массив групп в `contacts`: внешние ключи сами убирают связи при удалении контакта или группы. Переименование меняет одну строку
- `on delete cascade` с двух сторон: удалить группу - значит убрать её у контактов, а сами контакты не трогать. Удаление контакта уже удаляет заметки тем же способом
- Индекс по выражению, а не тип `citext`: `citext` не склеивает «ё» и «е», и это расширение Postgres, его надо включать отдельно. `lower` и `translate` неизменяемые функции, поэтому годятся для индекса
- Миграция генерируется `pnpm db:generate` (`drizzle/0002_*.sql`): только `CREATE TABLE`, `CREATE INDEX` и внешние ключи

### Код работы с группами - отдельный модуль

`src/lib/groups.ts` (`server-only`) - все чтения и записи групп. Функции возвращают результат или текст ошибки и ничего не знают о Next.js, поэтому их можно тестировать:

- `listGroups()` - все группы по названию, у каждой число контактов (`left join` + `count`)
- `findGroup(id)` - группа или ничего; по ней главная понимает, какая группа выбрана
- `createGroup(name)` - `insert ... on conflict do nothing returning id`. Пусто вернулось - «Такая группа уже есть»
- `renameGroup(id, name)` - `update ... returning id`. Ничего не обновилось - «Этой группы больше нет — возможно, её удалили». Ошибка уникальности (код Postgres `23505`; Drizzle кладёт исходную ошибку в `cause`) - «Такая группа уже есть». Смена только регистра или «е» на «ё» проходит: индекс сравнивает строку саму с собой
- `deleteGroup(id)` - `delete`. Если группы уже нет, ошибки нет
- `setContactGroups(tx, contactId, { groupIds, newGroupNames })` - внутри транзакции сохранения контакта:
  1. новые названия: `insert ... on conflict do nothing`, потом id всех этих групп по тому же ключу названия, что в индексе. Так «теннис» и «елка» из формы попадают в существующие «Теннис» и «Ёлку»
  2. удаляет все связи контакта и вставляет новые через `insert into contact_groups select ... from groups where id = any(...)`. Группы, которые успели удалить в другой вкладке, отбрасываются сами, без ошибки
- `listContactGroups(contactId)` - группы контакта по названию, для карточки и формы изменения

Server actions в `src/app/actions.ts` остаются тонкими: проверить ввод zod, вызвать функцию из `groups.ts`, обновить кэш, перейти на страницу.

Почему не писать в базу прямо в actions, как сейчас: action без Next.js не вызвать, а TDD нужны тесты на правила групп. Существующие actions контактов не переносим, только добавляем в `createContact` и `updateContact` транзакцию с `setContactGroups`.

Проверка названия - `groupNameSchema` в `src/lib/validation.ts`: `trim`, «Укажите название», «Не больше 50 символов». Схема общая для сервера и для поля «Новая группа» в форме (форма уже импортирует `validation.ts`). Там же `groupNameKey(name)` - ключ названия для браузера: `toLocaleLowerCase("ru")` и «ё» → «е», то же правило, что SQL-выражение в индексе.

### Фильтр по группе

- В адресе главной `group=<id>`. Разбор - `parseGroupId`, как `parseContactId`. Неправильное значение или удалённая группа (`findGroup` вернул пусто) - считаем, что выбрано «Все»
- `listContacts`, `countContacts` и `listOverdueContacts` получают необязательный `groupId`. Условие - `exists (select 1 from contact_groups where contact_id = contacts.id and group_id = $1)`, через `and` с условием поиска. У `listContacts` три параметра - переходим на объект `{ query, limit, groupId }`
- `listContacts` дополнительно возвращает `groupNames: string[]` - `array(select g.name ... order by g.name)` для строки списка. Подзапрос идёт по первичному ключу `contact_groups`
- Выбранная группа нужна трём серверным компонентам главной: ряду групп, блоку и списку. Чтобы не делать три запроса, `selectedGroup(searchParams)` обёрнут в `cache` из React

### Адреса и параметры главной

- Ссылки ряда групп сохраняют `q`, а `limit` и `due` сбрасывают: в новой группе - первые 50 и свёрнутый блок
- `SearchBox` при вводе сохраняет `group`, ставит или убирает `q`, остальное сбрасывает, как сейчас
- «Показать ещё» у списка и «Показать всех» / «Свернуть» у блока сохраняют `group`
- Ссылки на группу из карточки и со страницы «Группы» - `/?group=<id>`

### Экраны

Макета нет, всё собирается из того, что уже есть в приложении, только через дизайн-токены.

**Ряд групп на главной** - серверный компонент `GroupFilter` между заголовком «Контакты» и сообщением об удалении. Ряд стоит выше блока «Пора связаться», потому что фильтрует и блок, и список. Группы - ссылки, оформленные как кнопки переключателя частоты: выбранная - `default` с `aria-current="true"`, остальные - `outline`. На телефоне ряд переносится на несколько строк, без горизонтальной прокрутки. В конце - ссылка «Настроить группы» с иконкой шестерёнки. Пока групп нет - только «Создать группу» с плюсом.

**Список контактов** - под именем строка групп через « · » мелким приглушённым шрифтом, обрезается в одну строку. Видна на всех ширинах. Пустая группа - то же `EmptyState`, что и для пустого списка, с текстами из спеки. Счётчик и тексты «Никого не нашли…» учитывают группу.

**Форма контакта** - раздел «Группы» после почты, перед кнопками:

- существующие группы - метки с настоящими `checkbox name="groupId"`, оформленные как кнопки-переключатели. Отмеченная выглядит как выбранная кнопка. Работает без JavaScript
- поле «Новая группа» и кнопка «Добавить» (`type="button"`, Enter в поле работает так же и не отправляет форму) - в клиентском компоненте `GroupPicker`. Название проверяется `groupNameSchema`. Совпало с существующей по `groupNameKey` (без учёта регистра и разницы «ё» и «е») - отмечается она. Иначе появляется отмеченная метка новой группы со скрытым полем `newGroup`; снять отметку с новой - значит убрать её
- `ContactFormState.values` дополнительно хранит `groupIds` и `newGroupNames`, чтобы после ошибки в форме галочки и новые группы остались
- Список групп для формы страницы получают сами: `/contacts/new` и `/contacts/[id]/edit` вызывают `listGroups()`, форма изменения - ещё и `listContactGroups(id)`

Без JavaScript кнопка «Добавить» не работает: новую группу тогда можно создать на странице «Группы». Галочки и сохранение работают.

**Карточка** - строка «Группы» в списке сведений (`Detail`), после «Почты» и перед «В списке с»: ссылки через запятую цветом `rose`, как телефон и почта.

**Страница `/groups`** - как карточка контакта: `BackLink` «Все контакты», `Card` с заголовком «Группы»:

- сверху форма: поле «Новая группа» и кнопка «Создать». После успеха поле очищается: форма перерисовывается с новым ключом, как `ContactForm`
- ниже группы строками: название-ссылка на `/?group=<id>`, «N контактов» приглушённым цветом, кнопки «Переименовать» и «Удалить»
- «Переименовать» - ссылка на `/groups?edit=<id>`. Строка этой группы превращается в форму: поле с названием, «Сохранить», «Отмена» (ссылка на `/groups`). Работает без JavaScript, «Назад» закрывает редактирование
- «Удалить» - `DeleteGroupButton`, тот же `AlertDialog`, что у контакта, с текстами из спеки
- групп нет - «Групп пока нет» и подсказка, как у пустого списка контактов

### Обновление кэша

- Создание, переименование и удаление группы - `revalidatePath("/", "layout")`: название группы видно на главной, в карточках, в формах и на странице групп
- `createContact`, `updateContact`, `deleteContact` дополнительно обновляют `/groups`: там число контактов

### Тесты

- Vitest - последняя стабильная версия на момент установки, команда `pnpm test` (`vitest run`)
- Тестовая база - `<POSTGRES_DB>_test` в том же локальном контейнере Postgres. Новых строк в `.env` не нужно: имя выводится из `POSTGRES_DB`
- `globalSetup` создаёт тестовую базу, если её нет, и применяет миграции тем же мигратором Drizzle, что `src/db/migrate.ts`. `setupFiles` в каждом процессе тестов подставляет `POSTGRES_DB=<…>_test` до первого обращения к `db`, а перед каждым тестом очищает таблицы (`truncate ... restart identity cascade`)
- Защита: если имя базы не заканчивается на `_test`, настройка тестов падает до очистки таблиц. Рабочая база тестами не трогается никогда
- Файлы тестов идут по очереди (`fileParallelism: false`): база одна на всех
- `server-only` в тестах подменяется пустым модулем (`resolve.alias`), путь `@/` - тоже через `resolve.alias`. Без новых библиотек
- Тесты лежат рядом с кодом: `src/lib/groups.test.ts`, `src/lib/data.test.ts`, `src/lib/validation.test.ts`

### Тестовые данные Данте

В `seed-dante.ts` - отдельный шаг для групп после шага контактов. Он работает, даже если контакты Данте уже есть, и ничего не делает, если первая из групп Данте уже есть в базе. Группы и правила лежат в `seed-dante-data.ts`:

- около семи групп с названиями, которые вряд ли совпадут с настоящими: «Поэты», «Флорентийцы», «Ад», «Чистилище», «Рай», «Друзья юности», «Родня Алигьери»
- для героев поэмы - списки имён, для придуманных флорентийцев - правила по полю «Кто это» («уступ» → «Чистилище», «неба» → «Рай», «Поэт» → «Поэты» и т. п.)
- часть контактов сразу в двух-трёх группах; одна группа без контактов - на ней проверять «В группе … пока никого»

## Risks / Trade-offs

- [Тесты очистят рабочую базу, если перепутать настройки] → настройка тестов проверяет суффикс `_test` до любой записи; имя тестовой базы выводится из рабочего, а не задаётся отдельно
- [Группу удалили в другой вкладке ровно между проверкой и вставкой связи] → вставка связей идёт одним запросом из `groups`, в той же транзакции. Остаётся окно в доли секунды - для одного владельца это не случается
- [Браузер и база сравнят названия по-разному: форма отметит не ту группу или покажет новую, а база склеит её с существующей] → правило одно: замена «ё» на «е» и нижний регистр; тесты проверяют `groupNameKey` и то же самое на базе («Ёлка», «ЕЛКА», «елка»). Если всё же разойдутся, решает база: дубля не будет, контакт попадёт в существующую группу
- [Много групп - ряд на главной занимает несколько строк на телефоне и сдвигает список вниз] → для личной CRM групп обычно до десяти. Если станет мешать - отдельная правка
- [Строка групп под именем делает строки списка выше] → только у контактов с группами, одна строка с обрезкой
- [Группы под именем на телефоне повторяют то, что уже видно по выбранной группе] → это всё равно полезно: видно другие группы человека
- [Без JavaScript нельзя добавить новую группу из формы] → можно на странице «Группы»; остальная форма работает
- [Скрипт Данте добавит людей в группу с тем же названием, что уже создал владелец] → названия групп Данте подобраны так, чтобы не совпадать с обычными («Семья», «Друзья», «Теннис»); скрипт запускается только локально

## Migration Plan

1. `pnpm db:generate` создаёт `drizzle/0002_*.sql`; локально применяется `pnpm db:migrate`
2. На сервере всё как обычно: merge → образ → разовый контейнер `migrate` создаёт таблицы → стартует новый образ → smoke `/health`
3. Откат - только вручную, запускает владелец: предыдущий образ работает с новой базой, новые таблицы он не читает. Откатывать миграцию не нужно; если всё же нужно убрать таблицы - отдельная миграция с `DROP TABLE contact_groups, groups`, группы при этом потеряются
